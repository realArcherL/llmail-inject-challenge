Part one · Phi-3-medium (14B)

Where Phi-3 becomes readable

I wanted to fit a Jacobian lens on a small language model and see if that works.

Nishant JainSeptember 2026

My setup

Rented A100s on Modal. I fitted the lens with Anthropic's code, unmodified, on 100 passages of WikiText — 47 minutes, about $8 — then pointed it at 200 real prompt-injection attacks from Microsoft's LLMail-Inject challenge.

modal run lens_fit.py     # fit on WikiText, 47 min, one time
modal run lens_apply.py   # read the attack prompts, ~3 min

What it showed me

Most of the model is unreadable. I probed 30 facts, two phrasings each, four context lengths, every layer, through two lenses fitted on separate text. Nothing decodes below layer 21. It turns on sharply at 22, passes half at 24, and is perfect from 32.

The model's own output was already better. Telling attack emails from ordinary ones, the model's next-token probabilities scored 0.85. The lens at its best layer scored 0.81, and matched flag-for-flag the output equalled or beat every layer.

But it won in one place. At the end of the attacker's email — mid-prompt, where there is no output to read — the lens sometimes reads END, USER, SY: the model representing the attack as though a speaking turn had ended and someone else were about to talk. Which is what an injection structurally is. Across all 3,999 repeat-submitted attacks, with Microsoft's own outcomes as labels, that reading predicts which attacks work — and it isn't a restatement of the output signal.

The conclusion

It works. It's stable across two independent fits and it doesn't care how long the prompt is.

But on a model this size it will probably disappoint you, for a structural reason rather than a flaw in the method: the readable part of the network is the part nearest the output, so anything the lens can tell you, the output usually tells you sooner, cheaper and slightly better.

Reach for a lens when you need to read somewhere the output can't be read — mid-prompt, mid-generation. That's where mine found something. Not before.

Caveats

  • One model, microsoft/Phi-3-medium-128k-instruct. None of this transfers to a frontier model by default. Anthropic's work is on Claude.
  • My first scoring pass looked up answers by leading token id. Phi-3 splits digits, so every numeric answer got scored against a token decoding to an empty string — which invented a bump at layers 1–5 that doesn't exist. Fixed by scoring on decoded words.
  • This doesn't show Phi-3 knows it's being attacked. Representing text as a turn boundary is a structural fact, not a judgement.
  • Known-answer recall only. A layer could hold information the lens can't render as words.

Code and raw data: llmail-inject-challenge. Lens: anthropics/jacobian-lens, unmodified. Attacks: LLMail-Inject.

Model: microsoft/Phi-3-medium-128k-instruct, bfloat16. Lenses fitted on 100 WikiText passages each, 128 tokens, disjoint corpora. Probe: 30 facts × 2 framings × 4 depths × 39 layers × 2 lenses, scored on decoded top-5 words, restricted to probes the model itself answers. Attack labels: Microsoft's recorded outcomes over repeat submissions. Intervals are percentile bootstraps, 2,000 resamples.
